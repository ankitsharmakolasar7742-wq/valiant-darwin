Background & Motivation

Problem Statement & Proposed Solution

Voting Vulnerabilities

  • • Voter Impersonation: Unauthorized individuals voting on behalf of others or utilizing stolen credentials.
  • • Static Photo Spoofing: Attackers displaying printed photos, masks, or smartphone screens to fool conventional cameras.
  • • Double-Voting Fraud: Citizens exploiting jurisdictional gaps or latency to cast multiple ballots.

The BioVote Solution

  • ✓ SFace Deep Biometrics: Extracts 128-d invariant facial embeddings matched against enrolled profiles.
  • ✓ Active Liveness Challenge: Issues dynamic real-time physical actions (Blink, Turn Left/Right, Smile) to confirm live human presence.
  • ✓ Atomic Ballot Ledger: Enforces single-vote guarantee with cryptographic digital receipts.
Eliminates both digital replay attacks and physical proxy fraud in electronic elections.

Module 1 Implementation (Part 1)

Face Detection & SFace Biometric Recognition

1. Frame Capture
Webcam JPEG decoded to BGR matrix
2. YuNet CNN
Bounding box + 5 facial landmarks
3. Align & Crop
Affine normalization of head tilt
4. SFace 128-d
Extracts compact neural embedding
5. Cosine Match
Calculates cosine similarity ≥ 0.363
Mathematical Metric: Cosine Similarity Score = (u · v) / (||u||₂ · ||v||₂) Threshold: 0.363 for FAR 1e-3. Scores ≥ 0.363 confirm authentic identity (~70% - 100% confidence).
Why Lightweight ONNX Models?
  • • YuNet is only 232 KB; SFace is 38.6 MB.
  • • Operates at 30+ FPS purely on CPU without expensive GPUs.
  • • Invariant to illumination variations, distances, and minor head poses.

Face Recognition Python Code Architecture

face_engine.py (YuNet & SFace)
class FaceEngine:
    def __init__(self):
        self.detector = cv2.FaceDetectorYN_create(
            model=YUNET_PATH, config="", input_size=(320, 320),
            score_threshold=0.6, nms_threshold=0.3
        )
        self.recognizer = cv2.FaceRecognizerSF_create(
            model=SFACE_PATH, config=""
        )

    def extract_feature(self, bgr_img, face_data=None):
        if face_data is None:
            face_data, _ = self.detect_face(bgr_img)
        # Normalize and crop face using 5 landmarks
        aligned_face = self.recognizer.alignCrop(bgr_img, face_data)
        return self.recognizer.feature(aligned_face) # 128-d float array

    def compare_faces(self, feat1, feat2, cosine_threshold=0.363):
        score = self.recognizer.match(feat1, feat2, cv2.FaceRecognizerSF_FR_COSINE)
        is_match = bool(score >= cosine_threshold)
        pct = min(100.0, 70.0 + ((score - 0.363) / 0.287) * 30.0)
        return is_match, float(score), round(pct, 1)

Module 2 Implementation (Part 1)

Anti-Spoofing & Liveness Challenge Engine

Active Challenge-Response Defense: Defeats printed photo attacks, silicone masks, and smartphone video playback by issuing random physical challenges that must be executed live.

1. Eye Blink Challenge (EAR)

Monitors Left Eye (33, 160, 158, 133, 153, 144) & Right Eye (362, 385, 387, 263, 373, 380). Detects rapid EAR dip < 0.20 and rebound. Requires 2 sequential blinks.

2. Head Turn Left Challenge

MediaPipe 3D landmark mesh calculates head yaw angle via solvePnP & landmark ratios. User must turn head to their left and hold for 4 consecutive frames.

3. Head Turn Right Challenge

Evaluates mirrored 3D yaw angle threshold (Yaw < -14° or ratio > 0.62). Confirms volumetric 3D head movement impossible with a flat 2D photograph.

4. Dynamic Smile Challenge

Measures mouth width (landmarks 61 & 291) relative to face width (landmarks 234 & 454). Verifies genuine smile when ratio exceeds 0.44.

The challenge is selected randomly per voting session, preventing replay of pre-recorded videos.
Module 2 Implementation (Part 2)

Liveness Mathematics & Python Implementation

Eye Aspect Ratio (EAR) Formula: EAR = (||p₂ - p₆|| + ||p₃ - p₅||) / (2 · ||p₁ - p₄||)

Normal open eye EAR: ~0.28 - 0.35. EAR < 0.20 signals closed eye state. 2 consecutive transitions register verified blinks.

3D Head Pose via Perspective-n-Point (solvePnP):

Maps 3D canonical facial model points to 2D image coordinates (Nose 1, Chin 152, Eyes 33/263, Mouth 61/291) to compute Rodrigues matrix and Euler Yaw angle:

Yaw = arctan2(-R[2,0], sqrt(R[0,0]² + R[1,0]²))

Yaw > +14° = Turn Left; Yaw < -14° = Turn Right.

Voter Experience

PHASE 1
Voter Registration & Biometric Enrollment: Voter enters credentials and captures reference photo with live webcam snapshot or file upload.

6-Digit Email OTP Verification: Confirms email ownership. Includes on-screen simulated dispatcher for instant testing.
PHASE 3
Party Ballot Selection: Voter signs in, browses political candidates and manifestos, and clicks "Vote".
PHASE 4
Dual Biometric & Liveness Verification: Live camera verifies face match (>70%) AND completes the assigned physical challenge.
PHASE 5
Atomic Vote Cast & Digital Ballot Receipt: Database atomically records ballot, locks voter from voting again, and outputs printable receipt (VOTE-XXXXXXXX-XXXXXXXX).
Strict atomic transactions prevent race conditions and guarantee one voter, one vote.
